# 文档与代码注释中文化 — 原子需求清单

> 目标需求：把仓库内**全部文档翻译为中文**，把**全部代码注释改为中文**。
> 本文把该需求拆分为可独立交付、可独立验收的原子需求（DOC-01 ~ DOC-16、CMT-01 ~ CMT-17）。
> 与 `docs/localization-atomic-requirements.md`（I18N-01 ~ I18N-31）**平行**：
> I18N 管「应用运行时多语言能力」，本文管「仓库内文本中文化」，两者正交，可分别推进。
> 版本：v4（13 项决策已全部确认；见第 1 节与第 7 节）

### 2.4 与工程化相关的关键事实

| 事实 | 证据 | 影响 |
| --- | --- | --- |
| **17 个 `.ps1` 全部是无 BOM 的 UTF-8** | 全量字节检查 | Windows PowerShell 5.1 按 ANSI 读取 → 中文乱码、脚本语法破坏 |
| `.cs` 以 UTF-8 BOM 为主（306/330 抽样），`.md`/`.xaml`/`.idl` 无 BOM，`.resw` 有 BOM | 字节检查 | 需统一编码策略，否则中文写入非 BOM 文件存在解析风险 |
| `TreatWarningsAsErrors=true`（所有 .csproj）+ StyleCop 1.2.0-beta.556 + NET Analyzers（Recommended） | `Directory.Build.props` | 注释改动若触发分析器诊断即为**构建失败** |
| `.gitattributes` 为 `* text=crlf` | 仓库根 | 翻译会改写整文件 → diff 全量、评审成本高 |
| `.cpp`/`.h` 由 `clang-format` 格式化，项目未显式设置 `/utf-8` | `codeAnalysis/format_sources.ps1` | MSVC 可能按系统代码页解析中文注释（C4819） |
| extensionsdk 的 IDL 是对外公开的扩展契约 | `Microsoft.Windows.DevHome.SDK.idl`（413 行注释） | 改动会影响外部扩展作者看到的接口文档 |
| 3 个文件含 `<auto-generated>` 标记 | `*.Designer.cs`、两处 `TelemetryEventSource.cs` | 生成代码不得手改 |
| resw comment 列是 Loc 流水线的译者上下文输入 | 21 个 resw / 1,153 条目 / 1,018 条注释 | 与 I18N-27/29 的「仓库维护 vs Loc 输出」分工冲突 |

## 3. 非目标（明确排除）

1. `LICENSE`、`NOTICE.txt`、第三方许可与 `docs/sampleConfigurations` 中的 schema 字段名 —— 法律与技术标识不译。
2. resw 的 **value 列**、运行期 UI 文案、错误提示 —— 属 I18N-11 ~ I18N-15。
3. 日志、遥测事件名、WinGet 包 ID、命令行开关、注册表路径、环境变量名 —— 保持英文。
4. 自动生成代码：`NativeMethods.cs`（CsWin32）、`*.Designer.cs`、`TelemetryEventSource.cs` 的生成区段。
5. Git 提交历史、分支名、GitHub Issue/PR 正文（本次不回溯）。
6. 图片与截图中的英文文字（只译 Markdown 文本与 alt 文本）。
7. resw 的 **comment 列**：Loc 流水线的译者上下文字段，**保留英文**（决策 8），不计入中文覆盖率统计 —— 见 DOC-13。

- **CMT-02 注释中文化守则（代码结构保全）**
  - *范围*：只改注释文本；保留缩进、注释定界符、行尾对齐；**与原格式保持一致（决策 6）：不新增或删除注释行、不重排断行位置、不切换注释风格（`//` 不改成块注释、反之亦然）、不改源码任何字符**；保留 XML 文档标签（`<summary>`/`<param name>`/`<returns>`/`<see cref>`/`<inheritdoc>`）与 `cref` 引用；保留 `TODO/FIXME/HACK/BUG` 前缀与工单号；不翻译字符串字面量、日志文本、资源键、正则、URL；中英文/数字之间加半角空格（决策 5）。中文较长必须断行时，只能在原注释行合并语义（例如把 2 行英文注释压缩为 1 行中文并在原位置补 1 行空的注释行占位），确保文件总行数与每一行注释的起始位置不变。**例外（决策 13）**：极少数长注释确实无法在原文行结构内表达时，可在 CMT-02 的例外清单中登记（文件:行 + 理由），并在同一 PR 内修正受影响的 `#L###` 锚点；登记后的例外不再触发「不增删行」校验。

## 6. 主要风险

1. **PowerShell 编码**：17/17 个 `.ps1` 无 BOM，直接写中文会让 Windows PowerShell 5.1 按 ANSI 解析，轻则乱码、重则脚本语法错误导致构建/测试脚本失效。必须先做 CMT-03。
2. **警告即错误**：`TreatWarningsAsErrors=true` + StyleCop + NET Analyzers，注释改动可能触发 SA16xx/CS15xx 诊断直接构建失败。CMT-04 是硬闸门，不能省。
3. **行号锚点漂移**：docs 中 14 处 `#L###` permalink 指向源码行号（尤其 IDL）。决策 6 已锁定「注释与原格式一致、不增删行」，该风险基本消除，但这是**硬约束**：建议在每个 PR 的评审清单里加自动拦截（对每个文件校验 `git diff --numstat` 的增删行数相等）；确因特殊情况需要增删行时，必须在同一 PR 内修正受影响的 14 处锚点并在 PR 描述中说明。
4. **与 upstream 永久冲突**：纯中文替换英文后，`microsoft/devhome` 的后续提交在 docs 与注释上必然冲突，且无法自动合并。决策 7 的 `pre-zh-baseline` 标签只解决「能回看英文原文」，**不解决冲突本身**，仍需 DOC-14 的流程与持续人力预算。
5. **resw comment 与 Loc 流水线的取舍**：comment 是给译者的英文上下文，也是 Microsoft Loc 的输入。决策 8 选择保留英文，该冲突**已消解**，但需在 DOC-13 中落实两件事：① 补齐 135 条缺失 comment；② 在 I18N-27 白名单中登记「comment 列不受 Loc 下载覆盖」，否则未来 Loc 回传仍可能改写该列。
6. **评审不可读**：`.gitattributes` 为 `* text=crlf`，整文件翻译会产生全量 diff；决策 9 的「单 PR ≤ 800 行」把每个 PR 限制在可评审规模，PR 描述须写明「仅注释/文档变更」。
7. **语义漂移**：机翻容易把技术含义译错（例如 `compute system`、`setup flow`、`provider`、`elevation`），必须依赖 DOC-01 术语表 + 人工校对，不能一次性机翻合并。
9. **本地缺乏 C++/IDL 构建工具链**：实测 `cl.exe`（MSVC 编译器）与 `midl` **未安装**（仅 C++ 头文件/库存在，`VC\Tools\MSVC\...\bin` 缺失），`clang-format` 亦不在 PATH。后果：`extensionsdk`（C++/IDL，CMT-14）与 C++ 注释（CMT-13/CMT-12）的「编译 0 警告 / 0 新增诊断」无法在本地验证，只能在 CI（装有 VC++ 生成工具与 Windows SDK）或安装组件后验证。C# 侧（`dotnet` SDK 10.0.402）已实测含中文注释构建 0 警告，CMT-04 的 C# 部分已落地验证。建议把 C++/IDL 的构建闸门放到 CI 的 translations 专用 job 上做，而非依赖本地。
