# 代码注释中文化守则

> 关联原子需求：**CMT-02**（基线与规则，P0）
> 前置：`docs/zh-CN/glossary.md`（DOC-01 术语表与排版规则）
> 适用对象：全仓 1,243 个代码文件，约 14,977 行注释 + 514 行配置文件注释
> 版本：v1（2026-11-01）

## 1. 硬性约束（决策 6：与原格式保持一致）

1. **不新增、不删除注释行** —— 文件的总行数必须保持不变。
2. **不改缩进、不改注释风格**：`//` 仍是 `//`，`/* */` 仍是 `/* */`，`///` 仍是 `///`。
3. **不改任何非注释字符**：`git diff` 只允许出现注释行的变更。
4. 每个 PR 合并前用 `git diff --numstat` 校验：**每个文件的增删行数必须相等**（除登记在例外清单中的项，且例外应在同一 PR 内修正受影响的文档锚点）。

> 为什么这么硬：docs 里有 14 处指向源码行号的 permalink（`blob/<sha>/...#L###`），一旦行数漂移，这些链接全部失效。

如果中文确实比英文短很多需要「合并两行」，允许在原位置保留一行**空的注释占位**（如 `//`），而不是删除那一行。

**例外登记（决策 13）**：若某个文件的中文确实无法在原文行结构内表达（极少数长注释），允许破例 —— 在 `docs/chinese-translation-atomic-requirements.md` 第 7 节的例外清单中登记（文件:行 + 理由），并在同一 PR 内修正受影响的 `#L###` 锚点；登记后的例外不再触发「不增删行」校验。其余文件一律强制保持行数。

## 2. 必须保留、不得翻译的内容

| 类别 | 示例 | 处理 |
| --- | --- | --- |
| XML 文档标签 | `<summary>`、`<param name="vm">`、`<returns>`、`<see cref="ThemeSelectorService"/>`、`<inheritdoc/>` | 标签与 `name`、`cref` 的值保持原样，只译标签之间的文字 |
| `TODO`/`FIXME`/`HACK`/`BUG` 前缀与工单号 | `// TODO: Fix issue #1234` | 前缀与编号保留，说明部分翻译 |
| 编译器/工具指令 | `#pragma`、`// ReSharper disable`、`// NOLINT`、`// clang-format off`、`// <auto-generated>` | 一行都不许动 |
| 字符串字面量、日志文本、遥测事件名 | `Logger.Error("Failed to start")` | 不翻译（属 I18N-15 的非目标范畴） |
| 资源键、`x:Uid`、占位符 | `"Shell_Feedback"`、`{0}`、`ms-resource` | 不翻译 |
| 命令、路径、URL、正则、环境变量 | `winget install`、`%LOCALAPPDATA%` | 不翻译 |
| 语言标记 | `en-US`、`zh-CN` | 不翻译，且大小写保持原样 |
| `#region` / `#endregion` 名称 | `#region Setup` | 保留英文（IDE 折叠与 grep 都依赖它） |

## 3. 各类注释的规则

### 3.1 C# 的 `///` XML 文档注释

```csharp
// 原文
/// <summary>
/// Gets or sets the value indicating whether the extensions should be re-installed on first run.
/// </summary>
// 译文
/// <summary>
/// 获取或设置一个值，该值指示扩展是否应在首次运行时重新安装。
/// </summary>
```

- 多行原文要**保持行数**：2 行英文仍是 2 行中文，不要把 `<summary>` 起止行合并。
- `<param>` 的说明部分翻译，`name=` 的值不动。

### 3.2 `//` 行注释与行尾注释

```csharp
// 原文
// Extensions that support this provider type must return an object
// that implements the IComputeSystemProvider interface.
// 译文
// 支持此提供程序类型的扩展必须返回一个对象，
// 且该对象需实现 IComputeSystemProvider 接口。
```

- 行尾注释：`var count = 0; // Number of retries` → `var count = 0; // 重试次数`，保持在同一行。
- 一组多行注释内部允许跨行重新断句，但**总行数不能变**。

### 3.3 `/* */` 块注释（含 `common/Windows/SecondaryWindow.cs` 等大块）

- 按段落整段翻译，保留 `*` 行首对齐与块注释的星号围墙样式。
- 块注释里若嵌了代码样例（`XYZ` 之类），样例不译。

### 3.4 XAML `<!-- -->`

- 只译注释文字，不碰 `x:Uid`、绑定表达式。

### 3.5 PowerShell `#`

- 注释翻译；`#Requires`、`#region` 之类的指令行不动。
- `.ps1` 文件的编码处理见 **CMT-03**：写中文前必须确认 BOM。

### 3.6 IDL（`extensionsdk`）

- 公开 SDK 契约：语义必须与英文原文严格一致，不允许意译或省略条件。
- `[contract(...)]`、`[experimental]` 等属性行不动，只译属性上方的注释。
- 翻译后必须跑一次 `midl`，确认生成的契约未变。

### 3.7 配置文件（`.csproj` / `.props` / `.yml` / `.yaml` / `.appxmanifest` / `.xml`）

- 只译注释内容：MSBuild 的属性名、`PropertyGroup`、YAML 的键、任务的 `name` 一律不动。
- 改完要能被 `msbuild` / YAML 解析器正常读取。

## 4. 不翻译的情形

1. **生成代码**：含 `<auto-generated>` 标记的文件与区段（`NativeMethods.cs`、`*.Designer.cs`、`TelemetryEventSource.cs` 的生成区段）。
2. **你觉得「不用译」的短注释**（`// ok`、`// else`）—— 仍然要译，覆盖率统计会把它们算进来。唯一免译的是第 2 节列出的指令类。
3. 含义不明的缩写或自造标记（如 `// WM_foo` 之类的内部代号）：保留原文，并在 PR 里标注译者疑问，不要猜译。

## 5. 自检清单（每个 PR 必过）

- [ ] `git diff --numstat` 中每个文件的增删行数相等。
- [ ] `git diff` 没有触及任何代码行、字符串字面量、`<param name=...>` 的值。
- [ ] `see cref`、`<inheritdoc/>`、`TODO #1234` 完整保留。
- [ ] 术语与 `glossary.md` 一致；中英文之间有半角空格。
- [ ] `.ps1` 修改后仍带 UTF-8 BOM（CMT-03）。
- [ ] `msbuild` Release 构建 0 新增警告（CMT-04 的硬闸门：`TreatWarningsAsErrors=true`）。
- [ ] 该模块的中文覆盖率达到 100%（`build/scripts/Translation/CommentInventory.ps1 -Check`）。
